# 交互式数据分析工作台

离线版交互式数据分析工具，涵盖多源接入、查询分析、可视化图表、报告生成、异常检测与数据服务编排，所有分析配置与结果持久化到浏览器本地存储。

这是一个**纯前端**管理平台：React + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 通知送达中心

`通知分发` 页面在通用登记表之外带一套完整的送达台账，数据存在
`interactive-analytics-lab:notify-center`（与登记表的 `:entries` 分开）：

- **批次分离**：同时触发告警与报告时按消息类型分组，告警形成 `ALT-xxxx` 批次、报告形成
  `RPT-xxxx` 批次。报告永远新建独立批次并保留独立标识，不会被告警的合并逻辑吸收。
- **合并窗口**：同事件、同类型的告警在窗口内只记一次合并（`mergedCount`），窗口外则新建批次。
- **接收列表**：`并集` 纳入所有生效规则里出现过的接收人并去重；`交集` 只保留同时出现在
  每条生效规则里的接收人，被排除的人会在界面上列出来。
- **优先级冲突**：最高优先级相同但接收列表不同时，由登记顺序明确裁决；可选「明确规则裁决」
  （只按胜出规则名单发出）或「合并双方名单」。批次详情里保留完整裁决说明。
- **逐接收人落账**：每位接收人的失败重试次数单独计数；未达上限时批次停在该接收人，
  续发从最后失败的人继续；超过上限转入失败旁证并继续后面的接收人，不阻塞后续批次。
  已成功送达的接收人不会再进入发送路径，保证绝不二次送达。
- **渠道退订**：退订只跳过该渠道，同一接收人的其他渠道照常发送；全部渠道都退订才算跳过。
- **回执与旁证**：成功发送写 `RCPT-xxxx` 回执，失败/超时/回放旧消息/重试超限写 `EVD-xxxx`
  旁证，二者同时保留，可分别导出。
- **通道故障**：无响应、调用报错、回放旧消息三种状态可手动注入；发送失败只影响使用该通道的
  接收人。Webhook 回放旧消息不会产生成功回执。
- **残留批次**：发送中断（`sending`）、停在失败接收人（`paused`）或窗口过期未发的批次会被
  「残留批次定位」列出，可续发或清理；清理会作废未完成接收人，但保留已有的成功回执和失败旁证。

领域测试用 `npm run test:domain` 运行，覆盖上述规则。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`；通知送达的批次/回执/旁证走
  `frontend/src/api/notify-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `interactive-analytics-lab:entries` 这一项，或调用 `resetModule(模块)`；
  送达中心对应 `interactive-analytics-lab:notify-center`，页面上也有「恢复示例数据」。
